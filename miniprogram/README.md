# 原生微信小程序

使用微信开发者工具打开本目录。工程使用原生小程序语法，不依赖 uni-app 或 Taro。

## 联调前配置

1. 在 `project.config.json` 中将 `appid` 替换为微信公众平台的小程序 AppID（仓库中的默认值为空）。
2. `utils/request.js` 默认将 API 基址设为 `http://localhost:3000`，请求路径使用 `/api` 前缀以匹配后端 `app.use('/api', router)` 配置。真机请将其改成手机可访问的局域网地址，并按微信平台要求配置合法域名及 HTTPS。
3. 在后端环境变量中设置 `WX_APPID` 和 `WX_APP_SECRET`（不要写入小程序代码或提交到仓库）。登录接口 `POST /auth/login` 接收小程序 `wx.login()` 返回的 `code`，并在服务端换取 `openid`。
4. 微信开发者工具本地调试可以关闭“校验合法域名”，工程配置已将 `urlCheck` 设为 `false`。这不代表真机或线上环境可绕过微信的域名和 HTTPS 要求。

## 已使用的后端接口

- `POST /auth/login`：微信登录和保存用户联系电话，正文使用 `code`；报修表单要求填写联系电话，客户端通过此登录接口保存。
- `POST /order/create`：创建本人报修工单，正文使用 `title`、`desc`、`location`、`category`；页面要求选择故障类型。
- `GET /order/my`：读取当前登录用户的工单列表。
- `GET /order/:id`：读取本人工单详情。
- `GET /order/:id/messages`、`POST /order/:id/messages`：读取和发送本人报修的补充沟通，可附一张图片。
- `GET /user/profile`、`PUT /user/profile`：读取和更新当前用户昵称、联系电话。
- `POST /user/profile/avatar`：上传当前用户头像（JPG、PNG 或 WebP，最大 5MB）。
- `POST /order/:id/cancel`：撤销本人的待处理工单，撤销后保留记录并标记为已撤销。
- `DELETE /order/:id/my`：将本人的已完成或已撤销工单从用户端列表移除；后台仍保留历史记录。

小程序提供用户登录、工单状态筛选/搜索、报修草稿自动保存与草稿箱管理（多份保存、继续编辑、删除）、地图选点及地点二维码扫码预填、预计处理时限、本人报修补充沟通、个人资料维护、安全知识指南、完工评价分类及管理员回访展示等能力。地点二维码由管理后台生成，只预填楼栋、楼层和房间；用户应核对地点后再提交。报修草稿仅保存在当前设备，不会提交到服务器；图片只有在本地文件保存成功时才能随草稿恢复。成功提交工单后仅删除该份草稿。用户端不调用全部工单或修改状态接口。用户隐藏的工单仍保留在数据库和管理员后台。后端权限角色值仍为 `student`，无需变更数据库或令牌。现有创建接口要求 `title`，页面将故障描述前 30 个字符作为工单标题。列表项可打开工单详情。状态 `0/1/2` 的显示分别对应待处理、维修中、已完成；后端返回的中文状态“已撤销”也会显示为已撤销。地图选点需要微信定位授权，预计完成时间基于后端 SLA 配置且仅作估算。安全知识为静态内容，不提供自行拆卸/维修指导。本项目不实现微信订阅消息提醒。
